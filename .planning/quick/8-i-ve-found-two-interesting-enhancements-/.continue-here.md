<context>
The user wants Hebrew TTS to feel native — not like a separate "Hebrew mode" requiring
explicit model switching. The ideal is: pick "Hebrew Female (PiperStream)" from the voice
list, it just works (AgentTalk auto-switches engine + voice). Same UI pattern as switching
between af_heart and af_sky in Kokoro.

Key architectural question: currently voice is always within a model (af_heart is a Kokoro voice,
en_US-ryan is a Piper voice). Hebrew voices are tied to Hebrew engines. The design needs to
decide if we flatten this into a single voice namespace or keep model+voice explicit but
surface it more naturally.

Current voice picker flow: /agenttalk:voice → GET /voices → list → POST /config {voice: "..."}.
Hebrew voices currently need POST /config {model: "hebrewpiper", hebrewpiper_voice: "female"}.
The gap is exactly this extra step.
</context>
